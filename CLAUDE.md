# Математическая лаборатория — правила проекта

Банк интерактивных тренажёров по школьной математике. Ученики открывают
сайт по одной ссылке; каждый тренажёр — отдельная страница, где можно
менять параметры и сразу видеть, как меняется модель.

## Как начать работу в новом чате
1. Обновить папку: `git fetch && git checkout dev && git pull` (работаем только в `dev`).
2. Автопроверки локально: Python-окружение с `tests/requirements.txt`
   (`python -m venv … && pip install -r tests/requirements.txt && python -m playwright install chromium`),
   затем `python -m pytest tests -q`. Полный прогон — около 3 минут.
3. Показать результат учителю до публикации: локальный сервер из корня
   (`python3 -m http.server`) и встроенный браузер; после правок — Cmd+Shift+R (кэш).
4. Публикация — только когда учитель скажет: pull request `dev → main`,
   дождаться проверки, влить (можно автослиянием, если учитель согласен).
5. Учитель пишет по-русски и не программист: объяснять простыми словами,
   ответы задач перепроверять самостоятельно (решить вручную + `PL.solve.verify`).

## Стек и ограничения
- Чистые HTML + CSS + JS. Без React, без сборщиков, без npm.
- Каждая страница должна открываться двойным кликом (file://), поэтому:
  - НЕ использовать fetch() для локальных файлов;
  - каталог хранится в `catalog.js` (window.CATALOG = [...]), а не в JSON.
- Графика: SVG, рисуемый своим кодом (см. labs/graph-shifts как эталон).
  Внешние библиотеки (JSXGraph, KaTeX, Three.js) — только с CDN и только
  если без них правда сложно (стереометрия → Three.js).
- Весь интерфейс на русском.

## Структура
- `index.html` — каталог тренажёров, строится из `catalog.js`.
- `shared/style.css` — единый стиль (цвета, панели, ползунки). Новые
  тренажёры используют его классы, а не придумывают свои. Там же: `.frac`
  (дробь `<span class="frac"><span>5π</span><span>6</span></span>`), `.math` и
  `var(--font-math)` — шрифт формул, `.plot.static` — модель не мешает прокрутке.
  Ещё: тренировка (`.question`, `.ans-row`, `.keys`, `.status`, `.opts`/`.opt`), шаги разбора `.steps`,
  вкладки `.tabs`, заглушка вместо модели `.hidden-stage`, подпись к задаче `.src-note`. `Lab.frac(верх, низ)` — дробь в HTML.
- `shared/ui.js` — общие функции: `Lab.slider()`, `Lab.urlState`,
  `Lab.fmt()`, `Lab.copyLink(кнопка)` («Скопировать ссылку»).
- `labs/<slug>/index.html` — тренажёр. `labs/<slug>/spec.md` — ТЗ от учителя.

## Эталон
`labs/graph-shifts/` — образец. Новый тренажёр делай в том же устройстве:
шапка с «← Все тренажёры», панель параметров слева (на телефоне — снизу),
модель справа, блок «Задания» под моделью.

## Обязательно в каждом тренажёре
- Все параметры сохраняются в URL (?f=quad&p=2&q=-3) через `Lab.urlState`,
  чтобы учитель мог дать ссылку на конкретную настройку.
- Кнопка «Сбросить».
- Формула пересчитывается вживую и записывается так, как в учебнике
  (y = (x − 2)² + 3, а не y = (x + -2)^2 + 3). Минус — символ «−».
- Блок «Задания» в формате «предскажи → проверь».
- Работает на телефоне (ширина 375px), управление пальцем.
- Модель математически корректна: разрывы, асимптоты, области определения.
- После создания — добавить запись в `catalog.js`.

## Как писать код, чтобы он не разрастался
- **Математика отдельно от страницы.** Ответы, формулы, разбор ввода ученика —
  в `labs/<slug>/<имя>.js` без обращений к странице (DOM), с экспортом в
  `window.<Имя>` (как `PL` у «Задач с параметром», `TC` у окружности).
  Страница только рисует и реагирует на кнопки.
- **Каждый ответ — под автопроверкой.** `tests/test_<slug>.py` сверяет ответы
  с независимым подсчётом (перебор, численное решение), а не с той же
  формулой. Один раз нарочно испортить формулу и убедиться, что тест упал.
- **Повтор → в `shared/`.** Если кусок уже есть в другом тренажёре (стиль,
  кнопка, функция) — не копировать, а перенести в `shared/`. Общие файлы
  только дополнять: старое поведение не менять, после правки прогнать
  проверки всех тренажёров.
- **Один `update()`.** Обработчики кнопок меняют `state` и зовут `update()`;
  он пишет тексты, URL и перерисовывает модель. Не обновлять части
  страницы из разных мест.
- **Телефон.** У `.plot` по умолчанию запрещена прокрутка пальцем (чтобы
  тащить точки). Если в каком-то режиме модель не тащат — класс `static`,
  иначе страницу не прокрутить. Если осей мало — уменьшать `viewBox`,
  чтобы модель была крупнее.
- **Без лишнего.** Неиспользуемые переменные и функции удалять; одинаковые
  условия (`f === "sin" || f === "cos"`) — в функцию с понятным именем;
  одинаковые блоки (строка статуса, кнопки-плитки) — в маленький помощник.

## Как писать решения (разборы, шаги тренировочных задач, ответы к заданиям)
Учитель просит расписывать выкладки так, чтобы ученик мог повторить каждый шаг. Это касается
и готовых разборов, и решений, которые собирают генераторы, и задач банка.
- **Полный квадрат — всегда по шагам**, а не готовым ответом. По формуле
  $(u − k)^2 = u^2 − 2ku + k^2$: «$x^2 − 6x$: $2k = 6$, $k = 3$; $(x − 3)^2 = x^2 − 6x + 9$,
  поэтому $x^2 − 6x = (x − 3)^2 − 9$», затем подстановка и перенос чисел — и только потом
  «окружность с центром … и радиусом …».
- **Касание прямой и окружности — каждое действие отдельно:** записать прямую в виде
  $Ax + By + C = 0$; подставить центр и коэффициенты в формулу расстояния; приравнять радиусу;
  умножить на знаменатель; возвести в квадрат (оговорив, что обе части неотрицательны);
  раскрыть скобки; привести подобные; решить квадратное уравнение (разложить на множители или
  через дискриминант); и сказать, какой из корней подходит (верхняя/нижняя половина, концы дуги).
- Так же подробно — любая другая выкладка, из которой получается особое значение $a$.

## Перед тем как сказать «готово»
- Открыть страницу в браузере, убедиться, что в консоли нет ошибок.
- Проверить на ширине 375px и 1280px.
- Подвигать все ползунки в крайние положения.
- Прогнать автопроверки: `python -m pytest tests -v` (нужны пакеты из
  `tests/requirements.txt` и `python -m playwright install chromium`).

## Тренажёр «Задачи с параметром» (labs/parameters)
- ТЗ — `labs/parameters/spec.md`. Подтема = файл `topics/<id>.js`
  (`PL.topics.push({ memo, tasks, examples, generators })`), подключается в `index.html`
  и `editor.html`. Сейчас: `quad-roots`, `circle-line`, `graph-xy` (у неё `memo: []` —
  вкладка «Памятка» скрыта), `graph-xa` (сцены и задачи с `plane: "xa"`; вертикальная прямая —
  кривая `x = 2`, ОДЗ и отрезок — «при …» в самой кривой; ответ генератора собирает
  `S.fromBoundaries(особые a, a ↦ подходит ли число корней)`). Генератор возвращает задачу с точным ответом (`sets.quadIneq`,
  `intersect`) и шагами; автопроверка сверяет 30 задач каждого генератора.
- Движок: `engine/expr.js` (формулы по-школьному), `sets.js` (ответы-множества,
  точные числа (p + q√d)/n, распознавание 2√2 / log₂3 / π по приближению — `recognize`,
  `snap`), `solve.js` (подсчёт решений, карта ответа, проверка ответа), `plot.js` (рисование).
- Как считает `solve.js`: если одна кривая явная (y = …, x = …), решения — корни h(t) на
  сетке t = sinh(u) до |t| = 10⁴; неявная кривая, квадратная по y или x (окружность,
  гипербола), сама разбивается на явные ветви; только если не вышло — сетка на плоскости.
  Границы и касания на оси a уточняются и заменяются точными числами (`sets.snap`);
  выколотая граница ОДЗ определяется так же. `verify` проверяет ответ ещё и во всех
  найденных касаниях; `answerFromMap` — ответ «по графику» для подсказки конструктора.
- Диапазон `a` подбирается сам (`solve.fitRange`) по местам, где меняется число решений;
  `aRange` в задаче — только если нужен именно такой. На странице есть «Шире / Уже / Подобрать».
- Задача: `eq` — две части (кривые `y = …`, `x = …` или неявные), `ask` — `=2`,
  `>=1`, `inf`, `=1 при x > 0`; `plane: "xa"` — метод в плоскости (x; a).
- Задачи учителя — `bank/teacher.js`, правятся в «Конструкторе задач» (`editor.html`,
  `editor.js`): форма, живой график, проверка ответа, черновик в localStorage,
  кнопка «Скачать teacher.js» (файл целиком). Тексты разборов пишет Claude, учитель правит.
- Конструктор **не публикуется** (`deploy.yml` удаляет его из сборки) и не имеет ссылки
  со страницы тренажёра: в нём видны ответы банка. Учитель открывает его локально
  двойным кликом (file://), поэтому в нём, как и везде, нельзя `fetch()` локальных файлов.
- `engine/stage.js` — общая сцена (график, ползунок, карта ответа) для тренажёра и конструктора;
  стили обеих страниц — `param.css`.
- `tests/test_parameters.py` сверяет каждый ответ (разборы, генераторы × 30,
  банк) с численным подсчётом. Неверный ответ блокирует публикацию.

## Тренажёр «Тригонометрическая окружность» (labs/trig-circle)
- ТЗ — `labs/trig-circle/spec.md`. Режимы: окружность, уравнения, тренировки
  «градусы ↔ радианы» и «уравнения» (отметить точки → выбрать формулу).
- `trig.js` (`window.TC`) — вся математика: углы-дроби [n, d] = nπ/d, табличные
  числа-ключи (`"-s3/2"` = −√3/2), ответы, неверные варианты, разбор ввода.
- Ответ к sin x = a — двумя сериями: x = arcsin a + 2πn или x = π − arcsin a + 2πn
  (так просит учитель, без (−1)ⁿ).
- `tests/test_trig_circle.py` сверяет все ответы с перебором корней.

## Тренажёр «Тригонометрические выражения» (labs/trig-expr)
- ТЗ — `labs/trig-expr/spec.md`. Подтемы — `topics/double.js`, `reduction.js`, `values.js`, `find.js`,
  `mixed.js` (`TE.topics.push({ theory, tasks, examples, generators })`); страница — `app.js`, стили — `te.css`.
  У «Смешанных» `theory: []` — вкладка «Теория» скрыта, сцена по умолчанию — `scene` подтемы.
- `te.js` (`window.TE`) — точные числа n/d·√r (ответы без десятичных), разбор ввода ученика,
  мелочи для генераторов (`rad`, `bounded`, `sgnTxt`, `int`, `randSign`, `randUnit`) — не дублировать их в подтемах,
  правило лошади `reduce`, значение табличного угла любой величины с шагами `valueOf`
  (чётность → периоды → приведение → таблица), значения по одной функции `solveFrom`, генератор угла `given`.
- Сцена (`scene`) задаёт модель: `double` (deg — только табличные, unit), `reduction` (f, k, s, deg),
  `find` (gf, v, q), `angle` (deg до ±1440°, unit), `hide`.
- `tests/test_trig_expr.py`: 30 задач каждого генератора против численного счёта, правило лошади,
  `valueOf` для всех табличных углов до ±1440°, проверки разборов (`checks`), прохождение тренировки.

## Ветки и публикация
- `main` — опубликованный сайт (https://dv-grigorev.github.io/math-lab/).
  Напрямую в `main` не коммитить: ветка защищена, изменения попадают
  только через pull request с пройденной проверкой.
- Вся работа — в ветке `dev` (или `lab/<slug>` от неё). Её не видно на сайте.
- Готово → pull request `dev` → `main`. Workflow «Проверка»
  (`.github/workflows/check.yml`) прогоняет `tests/`. После слияния
  workflow «Публикация» (`deploy.yml`) ещё раз проверяет и выкладывает сайт.
  Если проверка упала — на сайте остаётся прошлая версия.
- На сайт копируются только `index.html`, `catalog.js`, `shared/`, `labs/`
  (без `*.md`). Новый общий файл в корне — добавить его в `deploy.yml`.
- При публикации к своим `.js`/`.css` в HTML дописывается `?v=<коммит>` —
  браузер ученика не смешает старые и новые файлы. Подключать файлы обычными
  относительными путями без `?v`, остальное сделает `deploy.yml`.
- Автопроверки (`tests/test_site.py`) для каждого тренажёра из `catalog.js`
  на 375px и 1280px: нет ошибок JS и консоли, нет битых файлов, нет
  горизонтальной прокрутки, есть «← Все тренажёры», «Сбросить», «Задания»;
  ползунки в крайние положения, все кнопки нажимаются. Каталог и папки
  `labs/` должны совпадать.
