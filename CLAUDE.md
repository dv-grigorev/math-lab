# Математическая лаборатория — правила проекта

Банк интерактивных тренажёров по школьной математике. Ученики открывают
сайт по одной ссылке; каждый тренажёр — отдельная страница, где можно
менять параметры и сразу видеть, как меняется модель.

## Стек и ограничения
- Чистые HTML + CSS + JS. Без React, без сборщиков, без npm.
- Каждая страница должна открываться двойным кликом (file://), поэтому:
  - НЕ использовать fetch() для локальных файлов;
  - каталог хранится в `catalog.js` (window.CATALOG = [...]), а не в JSON.
- Графика: SVG, рисуемый своим кодом (см. labs/graph-shifts как эталон).
  Внешние библиотеки (JSXGraph, KaTeX, Three.js) — только с CDN и только
  если без них правда сложно (стереометрия → Three.js).
- Весь интерфейс на русском.

## Структура
- `index.html` — каталог тренажёров, строится из `catalog.js`.
- `shared/style.css` — единый стиль (цвета, панели, ползунки). Новые
  тренажёры используют его классы, а не придумывают свои.
- `shared/ui.js` — общие функции: `Lab.slider()`, `Lab.urlState`,
  `Lab.fmt()`, `Lab.toggle()`.
- `labs/<slug>/index.html` — тренажёр. `labs/<slug>/spec.md` — ТЗ от учителя.

## Эталон
`labs/graph-shifts/` — образец. Новый тренажёр делай в том же устройстве:
шапка с «← Все тренажёры», панель параметров слева (на телефоне — снизу),
модель справа, блок «Задания» под моделью.

## Обязательно в каждом тренажёре
- Все параметры сохраняются в URL (?f=quad&p=2&q=-3) через `Lab.urlState`,
  чтобы учитель мог дать ссылку на конкретную настройку.
- Кнопка «Сбросить».
- Формула пересчитывается вживую и записывается так, как в учебнике
  (y = (x − 2)² + 3, а не y = (x + -2)^2 + 3). Минус — символ «−».
- Блок «Задания» в формате «предскажи → проверь».
- Работает на телефоне (ширина 375px), управление пальцем.
- Модель математически корректна: разрывы, асимптоты, области определения.
- После создания — добавить запись в `catalog.js`.

## Перед тем как сказать «готово»
- Открыть страницу в браузере, убедиться, что в консоли нет ошибок.
- Проверить на ширине 375px и 1280px.
- Подвигать все ползунки в крайние положения.
- Прогнать автопроверки: `python -m pytest tests -v` (нужны пакеты из
  `tests/requirements.txt` и `python -m playwright install chromium`).

## Тренажёр «Задачи с параметром» (labs/parameters)
- ТЗ — `labs/parameters/spec.md`. Подтема = файл `topics/<id>.js`
  (`PL.topics.push({ memo, tasks, examples, generators })`), подключается в `index.html`.
- Движок: `engine/expr.js` (формулы по-школьному), `sets.js` (ответы-множества,
  точные числа (p + q√d)/n), `solve.js` (численный подсчёт решений, карта ответа,
  проверка ответа), `plot.js` (рисование).
- Задача: `eq` — две части (кривые `y = …`, `x = …` или неявные), `ask` — `=2`,
  `>=1`, `inf`, `=1 при x > 0`; `plane: "xa"` — метод в плоскости (x; a).
- Задачи учителя — `bank/teacher.js`. Тексты пишет Claude, учитель правит.
- `tests/test_parameters.py` сверяет каждый ответ (разборы, генераторы × 30,
  банк) с численным подсчётом. Неверный ответ блокирует публикацию.

## Ветки и публикация
- `main` — опубликованный сайт (https://dv-grigorev.github.io/math-lab/).
  Напрямую в `main` не коммитить: ветка защищена, изменения попадают
  только через pull request с пройденной проверкой.
- Вся работа — в ветке `dev` (или `lab/<slug>` от неё). Её не видно на сайте.
- Готово → pull request `dev` → `main`. Workflow «Проверка»
  (`.github/workflows/check.yml`) прогоняет `tests/`. После слияния
  workflow «Публикация» (`deploy.yml`) ещё раз проверяет и выкладывает сайт.
  Если проверка упала — на сайте остаётся прошлая версия.
- На сайт копируются только `index.html`, `catalog.js`, `shared/`, `labs/`
  (без `*.md`). Новый общий файл в корне — добавить его в `deploy.yml`.
- Автопроверки (`tests/test_site.py`) для каждого тренажёра из `catalog.js`
  на 375px и 1280px: нет ошибок JS и консоли, нет битых файлов, нет
  горизонтальной прокрутки, есть «← Все тренажёры», «Сбросить», «Задания»;
  ползунки в крайние положения, все кнопки нажимаются. Каталог и папки
  `labs/` должны совпадать.
